# Glosario de conceptos

Contexto compacto para la IA: un concepto por línea, con su definición. Generado automáticamente.

- **Alucinación**: Respuesta de un modelo de lenguaje que suena plausible pero es falsa o no está respaldada por fuentes.
- **Atomicidad**: Principio fundamental del Modelo Relacional que establece que el valor de cada Atributo debe ser indivisible.
- **Atributo**: Propiedad o característica que describe a una Entidad en el modelo de datos.
- **Atributo Compuesto**: Atributo que puede subdividirse en partes más pequeñas, cada una con su propio significado independiente.
- **Atributo Multivaluado**: Característica de una Entidad que puede contener múltiples valores para un único registro.
- **Base de conocimiento**: Conjunto de hechos y reglas que un sistema experto usa para razonar.
- **Base de Datos**: Colección estructurada de datos lógicamente coherentes que representan entidades del mundo real.
- **Base de Datos Relacional**: Modelo que organiza la información en tablas interconectadas.
- **Cardinalidad**: Restricción que define el número de ocurrencias de una Entidad que pueden relacionarse con otra en un MER.
- **CRUD**: Acrónimo de Create, Read, Update y Delete: las cuatro operaciones básicas sobre los datos.
- **CTE**: Consulta temporal con nombre, definida con WITH al inicio de una sentencia, que se usa como si fuera una tabla.
- **Dato**: Unidad mínima de información, desprovista de contexto o interpretación por sí misma.
- **DOM**: Document Object Model: representación en forma de árbol de un documento HTML, que JavaScript puede leer y modificar.
- **Entidad**: Representación abstracta de un objeto, persona, concepto o evento del mundo real que es relevante para el sistema de información.
- **Escalabilidad**: Capacidad de un sistema para atender más carga.
- **Evento programado**: Tarea que el servidor ejecuta según un calendario o una sola vez.
- **Función de ventana**: Función que calcula un valor para cada fila usando un conjunto de filas relacionadas, definido con la cláusula OVER, sin agrupar ni reducir el número de filas.
- **Function calling**: Mecanismo por el que un modelo solicita ejecutar una función definida por la aplicación, con argumentos estructurados, y luego usa el resultado en su respuesta.
- **Herencia**: Mecanismo por el que una clase hereda atributos y métodos de otra, la clase padre, y puede extenderlos o modificarlos.
- **Información**: Conjunto organizado de datos procesados que poseen un significado, contexto y propósito dentro de un sistema.
- **JOIN**: Operación que combina filas de dos o más tablas según una condición, normalmente la coincidencia entre una llave foránea y su llave primaria.
- **JSON**: Formato de texto ligero para representar datos semiestructurados con pares clave-valor y arreglos.
- **Llave Foránea (FK)**: Un campo en una tabla que establece un vínculo lógico con la Llave Primaria de otra tabla (o la misma).
- **Llave Primaria (PK)**: Un Atributo o conjunto de atributos que identifica de manera única e inequívoca a cada Tupla dentro de una Tabla.
- **Llaves (Base de Datos)**: Mecanismos de integridad que permiten identificar, relacionar y restringir los registros dentro de una estructura relacional.
- **Model Context Protocol (MCP)**: Protocolo abierto que estandariza la forma en que un modelo de IA se conecta con herramientas y fuentes de datos externas.
- **Modelo de lenguaje de gran escala (LLM)**: Red neuronal entrenada con enormes volúmenes de texto para predecir el siguiente fragmento de texto.
- **Modelo Entidad-Relación (MER)**: Técnica de modelado conceptual utilizada en la fase de requerimientos para representar la estructura de datos mediante diagramas E-R.
- **Modelo Lógico Relacional**: Etapa de diseño donde el MER se transforma en una estructura de tablas lista para ser implementada en un SGBD.
- **Motor de inferencia**: Componente de un sistema experto que aplica las reglas de la base de conocimiento a los hechos para deducir nuevas conclusiones.
- **MySQL**: Sistema de gestión de bases de datos relacionales de código abierto.
- **Node.js**: Entorno de ejecución que permite ejecutar JavaScript fuera del navegador.
- **Normalización**: Proceso de diseño que organiza las tablas para reducir la redundancia y evitar anomalías al insertar, actualizar o borrar datos.
- **Patrón de diseño**: Solución probada y reutilizable para un problema recurrente de diseño de software, descrita como una plantilla que se adapta al caso concreto.
- **Persistencia de datos**: Capacidad de conservar los datos más allá de la ejecución del programa, por ejemplo en archivos o en una base de datos.
- **Polimorfismo**: Capacidad de tratar objetos de distinto tipo mediante una misma interfaz, de modo que cada uno responde a su manera al mismo mensaje.
- **Pool de conexiones**: Conjunto de conexiones abiertas y reutilizables que la aplicación comparte, en lugar de abrir una nueva por cada consulta.
- **PostgreSQL**: Sistema de gestión de bases de datos relacionales de código abierto, conocido por su extensibilidad y su soporte para tipos como JSON y XML.
- **Prepared statement**: Sentencia SQL con marcadores de posición para los valores.
- **Principios SOLID**: Cinco principios de diseño orientado a objetos: responsabilidad única, abierto/cerrado, sustitución de Liskov, segregación de interfaces e inversión de dependencias.
- **Procedimiento almacenado**: Bloque de sentencias SQL guardado en el servidor, que se invoca por nombre y puede recibir parámetros.
- **Programación orientada a objetos**: Paradigma que organiza el código en objetos, que combinan datos y comportamiento, normalmente definidos a partir de clases.
- **Prompt**: Instrucción o contexto que se le da a un modelo para obtener una respuesta.
- **Red neuronal**: Modelo computacional inspirado en las neuronas biológicas: capas de nodos conectados por pesos que se ajustan durante el entrenamiento para aprender patrones a partir de datos.
- **Relación entre entidades**: Vínculo semántico entre dos o más entidades.
- **Sistema experto**: Programa que resuelve problemas en un dominio especializado aplicando una base de conocimiento y reglas de inferencia, y que puede explicar sus razonamientos.
- **Sistema Gestor de Base de Datos (SGBD)**: Un SGBD es una capa de software compleja que actúa como intermediario entre los usuarios finales y los datos almacenados físicamente.
- **SQL**: Lenguaje estándar para definir, consultar y manipular datos en bases de datos relacionales.
- **Tabla (Base de Datos)**: Estructura fundamental para organizar información en filas y columnas.
- **Testing automatizado**: Verificación del comportamiento del software mediante pruebas que se ejecutan automáticamente, para detectar errores de forma repetible.
- **Transacción**: Conjunto de operaciones que se ejecutan como una sola unidad: o se completan todas o no se aplica ninguna.
- **Trigger**: Bloque de código que se ejecuta automáticamente cuando ocurre un INSERT, UPDATE o DELETE sobre una tabla, antes (BEFORE) o después (AFTER) de la operación.
- **Tupla**: En el modelo relacional, una tupla (o registro) representa una ocurrencia única o instancia de una entidad dentro de una Tabla.
- **Vista**: Consulta guardada con nombre que se usa como si fuera una tabla.
- **XML**: Lenguaje de marcas que organiza la información en etiquetas anidadas.
- **Índice**: Estructura auxiliar que permite localizar filas por el valor de una o más columnas sin recorrer toda la tabla.
