# Patrón de diseño

<!-- auto:categoria -->
Categoría: [Ingeniería de software](categoria.md)
<!-- /auto:categoria -->

Un **patrón de diseño** es una solución probada y reutilizable para un problema recurrente de diseño de software. Se describe como una plantilla que se adapta al caso concreto, no como un fragmento de código que se copia tal cual.

## Familias

Los patrones clásicos se agrupan en tres familias:

* **Creacionales:** cómo se crean los objetos, como el *Factory Method*.
* **Estructurales:** cómo se combinan objetos y clases, como el *Adapter*.
* **De comportamiento:** cómo se comunican los objetos, como el *Observer*.

El [DTO](dto.md) también se considera un patrón: define un objeto simple para transportar datos entre capas.

## Cuándo usarlos

Un patrón se justifica cuando resuelve un problema real. Aplicarlo sin necesidad añade complejidad sin beneficio. La mejor solución es la que resuelve el problema con la complejidad razonable.
